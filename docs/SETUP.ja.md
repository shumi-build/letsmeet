# セットアップ手順（日本語）

このリポジトリを clone して、**自分の Google Cloud と Cloudflare** で Let's Meet を公開し、友達が本物の Google カレンダーをつないで使える状態にするまでの手順です。コードを書く必要はありません。必要なのは、あなたのアカウントでの設定だけです。

## 全体の流れ

| 段階 | やること | 時間の目安 | お金 |
|---|---|---|---|
| ステップ1 | アカウントを守る（2段階認証） | 15分 | 無料 |
| ステップ2 | Cloudflare に公開する（仮のURLで） | 20分 | 無料 |
| ステップ3 | Google Cloud の設定 | 30分 | 無料 |
| ステップ4 | 2つをつないで、友達とテストする | 15分 | 無料 |
| ステップ5 | 独自ドメインと Google の審査（一般公開するとき） | 1時間＋審査待ち数日〜数週間 | ドメイン代 年1,500〜2,000円ほど |

**ステップ1〜4までやれば、Google アカウントを登録した友達（最大100人）とすぐに使えます。** ステップ5は、誰でも使えるようにしたくなったときで大丈夫です。

> Google Cloud や Cloudflare の画面は、ときどき名前や配置が変わります。見当たらないときは、項目名（例：「承認済みの JavaScript 生成元」）で画面内を探してください。

## ステップ1：アカウントを守る（いちばん大事）

このアプリのセキュリティは「サーバーに危ないデータを置かない」設計にしてあります。それでも残る最大のリスクは、**あなたの管理用アカウントが乗っ取られて、サイトを書き換えられること** です。なので、最初にここを固めます。

### Google アカウント（Google Cloud に使うアカウント）

1. https://myaccount.google.com/security を開く
2. 「Google へのログイン」の欄で **パスキー** を作成する（iPhone の Face ID / Mac の Touch ID で入れるようになる）
3. 同じ欄の **2段階認証プロセス** をオンにする

### Cloudflare アカウント

ステップ2でアカウントを作ったあとに、次の設定をします。

1. 右上の人のアイコン →「My Profile」→「Authentication」
2. **Two-Factor Authentication** をオンにする（認証アプリ、またはパスキー / セキュリティキー）
3. 表示される **バックアップコード** を、パスワード管理アプリなど安全な場所に保存する

### GitHub（コードを GitHub に置くときだけ）

今はまだ GitHub に置いていないので、置くときに設定すれば十分です。Settings → Password and authentication → Passkeys / Two-factor authentication。

## ステップ2：Cloudflare に公開する（仮のURLで）

まずはドメインを買わずに、Cloudflare が無料でくれる `〜.workers.dev` というURLで公開します。

### 2-1. アカウントを作る

1. https://dash.cloudflare.com/sign-up でアカウントを作る（メールアドレスとパスワード）
2. 届いた確認メールのリンクを押す
3. ここで **ステップ1の Cloudflare の2段階認証** を設定しておく

### 2-2. 仮のURLの名前を決める

1. ダッシュボードの左メニューで「**Workers & Pages**」（または「Compute (Workers)」）を開く
2. 初めて開くと、`〜.workers.dev` のサブドメイン名を決める画面が出るので、好きな名前を入れる（例：`your-name`）
   - これで公開URLは `https://letsmeet.your-name.workers.dev` のようになります
   - 画面が出なければ、Workers & Pages の画面右側にある「Subdomain」で確認・変更できます

### 2-3. コードを手元に用意して、Cloudflare にログインする

Node.js（20 以上）が入ったパソコンで、ターミナルを開いて次を実行します（`<このリポジトリのURL>` は GitHub の「Code」ボタンで表示される URL）。

```bash
git clone <このリポジトリのURL> letsmeet
```

```bash
cd letsmeet && npm install
```

ログインします。ブラウザが開くので「**Allow**」を押してください。

```bash
npx wrangler login
```

ターミナルに `Successfully logged in` と出れば成功です。

### 2-4. 公開する

```bash
npm run deploy
```

最後に次のようなURLが表示されます。**このURLをメモしてください（ステップ3で使います）。**

```
https://letsmeet.your-name.workers.dev
```

そのURLをスマホで開いて「New plan」の画面が出れば成功です。この時点で「Googleカレンダーをつなぐ」を押すと「まだ設定が済んでいません」と出ますが、それで正常です（ステップ3〜4で直ります）。

## ステップ3：Google Cloud の設定

ここがいちばん画面が多いところです。やることは「Google に『このアプリは、予定が入っている時間だけを見たい』と登録する」だけです。

**作らなくていいもの**：APIキー、サービスアカウント、請求先アカウント（お金の登録）。どれも不要です。

> Google Cloud の画面は日本語/英語どちらでも構いません。以下は日本語表示の名前で書いて、英語名を（ ）に入れています。2025年から「OAuth 同意画面」は「**Google Auth Platform**」という名前の画面に変わっています。

### 3-1. プロジェクトを作る

1. https://console.cloud.google.com/ を開く（ステップ1で守った Google アカウントで）
2. 初めてなら利用規約に同意する
3. 画面上部の **プロジェクト選択**（「プロジェクトを選択」と書かれたボタン）→ 右上の「**新しいプロジェクト**」
4. プロジェクト名：`letsmeet`、組織：「組織なし」のまま →「**作成**」
5. 作成が終わったら、画面上部のプロジェクト選択が `letsmeet` になっていることを確認する

### 3-2. Google Calendar API を有効にする

1. 左上の「≡」メニュー →「**API とサービス**」→「**ライブラリ**」
2. 検索欄に `Google Calendar API` と入れて、出てきた **Google Calendar API** を開く
3. 「**有効にする**（Enable）」を押す

### 3-3. アプリの登録（Google Auth Platform）

1. 左上の「≡」メニュー →「**Google Auth Platform**」（または「API とサービス」→「OAuth 同意画面」）
2. 「**開始**（Get started）」を押すと、4つの質問が順に出ます
   - **アプリ情報**：アプリ名 `Let's Meet`、ユーザーサポートメール＝あなたのメールアドレス
   - **対象**（Audience）：「**外部**（External）」を選ぶ
   - **連絡先情報**：あなたのメールアドレス
   - **終了**：ポリシーに同意して「作成」
3. 作成が終わると、左側に「ブランディング」「対象」「クライアント」「データアクセス」などのメニューが並んだ画面になります

### 3-4. 権限（スコープ）を「空き時間だけ」に絞る

ここが **セキュリティ上いちばん大事な設定** です。

1. 左メニューの「**データアクセス**（Data Access）」→「**スコープを追加または削除**」
2. 右から出てくる一覧の上のフィルタ欄に `freebusy` と入力する
3. API 欄が **Google Calendar API**、スコープ欄が **`.../auth/calendar.freebusy`** で終わっている行に **1つだけ** チェックを入れる
   - 説明文は「Google カレンダーの空き時間情報を表示」のような文言です
   - `calendar` や `calendar.readonly` や `calendar.events` など、**ほかのスコープには絶対にチェックを入れない**（予定の中身まで読めてしまうため）
4. 下の「**更新**」→ 画面の一番下の「**保存**」
5. 保存後、「機密性の高いスコープ」の欄に `calendar.freebusy` が **1つだけ** 並んでいれば完了です

### 3-5. テストユーザーを登録する

審査を通す前の「テスト」状態では、ここに登録した Google アカウントの人だけが使えます（最大100人）。

1. 左メニューの「**対象**（Audience）」
2. 「公開ステータス」が「**テスト**（Testing）」になっていることを確認する（**「アプリを公開」はまだ押さない**）
3. 「テストユーザー」の「**＋ Add users**」→ 自分と友達の **Gmail アドレス** を入れて保存する
   - 友達のアドレスはあとからいつでも追加できます

### 3-6. クライアント ID を作る

1. 左メニューの「**クライアント**（Clients）」→「**＋ クライアントを作成**」
2. アプリケーションの種類：「**ウェブ アプリケーション**」
3. 名前：`Let's Meet web`
4. 「**承認済みの JavaScript 生成元**」の「＋ URI を追加」で、次の2つを入れる
   - ステップ2-4でメモしたURL（例：`https://letsmeet.your-name.workers.dev`）
   - `http://localhost:8787`（自分のパソコンで本物の Google を試すとき用）
   - **注意**：最後に `/` を付けない。`https://` から完全に一致させる
5. 「**承認済みのリダイレクト URI**」は **空のまま**（このアプリは使いません）
6. 「**作成**」を押す
7. 表示された **クライアント ID**（`1234…-abcd….apps.googleusercontent.com` のような文字列）をコピーする
   - 同時に「クライアント シークレット」も表示されることがありますが、**このアプリでは使いません**。ダウンロードもコピーもしなくて大丈夫です。誰にも渡さないでください
   - クライアント ID のほうは秘密ではありません（サイトを見れば誰でも分かる、公開してよい識別子です）

## ステップ4：2つをつないで、友達とテストする

### 4-1. クライアント ID をアプリに入れる

プロジェクトのフォルダで `.env.example` をコピーして `.env` を作ります。

```bash
cp .env.example .env
```

`.env` をテキストエディタで開き、`VITE_GOOGLE_CLIENT_ID=` のあとにコピーしたクライアント ID を貼って保存します。`.env` は git に含まれない設定になっています。

### 4-2. もう一度公開する

クライアント ID は公開するときにアプリに組み込まれるので、**`.env` を書いたあとに必ずもう一度公開** します。

```bash
npm run deploy
```

### 4-3. 自分で試す

1. スマホで公開URLを開き、予定を作る →「自分の予定を入れる」→「**Googleカレンダーをつなぐ**」→「Googleで続ける」
2. Google の画面で、ステップ3-5で登録したアカウントを選ぶ
3. 「**Google でこのアプリは確認されていません**」という警告が出ます。テスト中はこれが正常です
   - 「**詳細**」→「**Let's Meet（安全ではないページ）に移動**」
4. 許可を求める画面に「**Google カレンダーの空き時間情報の表示**」**だけ** が書かれていることを確認して「続行」
5. カレンダーの予定が自動で入れば成功です

**ちゃんと権限が外れているかの確認**：https://myaccount.google.com/connections を開いて、Let's Meet が一覧に残っていないこと（または「空き時間情報の表示」だけになっていること）を確認します。アプリは読み取りが終わるとすぐ権限を取り消す作りなので、通常は一覧に残りません。

### 4-4. 友達とテストする

1. 友達の Gmail アドレスを、ステップ3-5のテストユーザーに追加する
2. 予定のリンクを LINE で送る
3. 友達に「Google の『確認されていません』という画面が出るけど、『詳細』→『移動』で進んで大丈夫」と一言伝えておく

## ステップ5：一般公開するとき（独自ドメインと Google の審査）

テストユーザー以外の人も使えるようにするには、Google の審査が必要です。審査にはあなたのドメインとプライバシーポリシーのページが必要なので、ここでドメインを用意します。

### 5-1. ドメインを買って、サイトにつなぐ

1. Cloudflare ダッシュボードの左メニュー「**Domain Registration**（ドメインの登録）」→「**Register Domains**」
2. 欲しい名前を検索して購入する（`.com` で年1,500〜2,000円ほど。原価販売なので他社より安いことが多いです）
3. 「**Workers & Pages**」→ `letsmeet` →「**設定**（Settings）」→「**ドメインとルート**（Domains & Routes）」→「**追加**」→「**カスタムドメイン**」→ 買ったドメイン（例：`letsmeet.app`）を入れる
4. 数分後に `https://買ったドメイン` で開ければ完了です

### 5-2. Google 側をドメインに合わせる

1. Google Auth Platform →「**クライアント**」→ `Let's Meet web` → 承認済みの JavaScript 生成元に `https://買ったドメイン` を追加して保存
2. 「**ブランディング**（Branding）」で次を入れて保存
   - アプリのホームページ：`https://買ったドメイン`
   - プライバシーポリシーのリンク：`https://買ったドメイン/privacy`
   - 承認済みドメイン：`買ったドメイン`
   - アプリのロゴ（任意。審査を早くしたいなら入れる）
3. ドメインの所有確認：https://search.google.com/search-console で「ドメイン」を追加し、表示される `TXT` レコードを Cloudflare の「DNS」→「レコードを追加」で登録する（Cloudflare で買ったドメインなら、ボタン1つで自動登録できる画面が出ることもあります）

### 5-3. 審査に出す

1. Google Auth Platform →「**対象**」→「**アプリを公開**」
2. 「**確認センター**（Verification Center）」から審査を申請する。聞かれることと、答えの例：
   - **スコープを使う理由**（英語で書くのが無難です）：
     > Let's Meet helps a group of friends find dates when everyone is free. We request only calendar.freebusy to read the user's busy time ranges within the plan's dates, so we can fill in their availability automatically. The request runs entirely in the user's browser, the access token is revoked immediately after one free/busy query, and no event titles, details, email addresses or Google data are sent to or stored on our server.
   - **デモ動画**：スマホの画面録画で「予定を作る → Googleカレンダーをつなぐ → 許可画面（スコープが見えるように）→ 空き時間が入る」までを撮り、YouTube に「限定公開」でアップしてURLを貼る
3. 審査は数日〜数週間かかります。Google からメールで質問が来たら、そのメールに返信して答えます

### 5-4. 審査の前にコード側でやること

- `.env` の `VITE_CONTACT_EMAIL` に連絡先メールアドレスを書く（`/privacy` ページに表示されます。審査で必要）
- Google カレンダーのマークを Google 公式のブランド素材に差し替える（`app/src/ui/dom.ts` の `GCAL`）
- 書き換えたら `npm run deploy` でもう一度公開する

## 困ったとき

| 症状 | 原因と直し方 |
|---|---|
| 「Googleカレンダーの設定が済んでいません」と出る | `.env` を書いたあとに `npm run deploy` をし直していない。もう一度公開する |
| Google の画面に「アクセスをブロック：このアプリはテスト中です」 | そのアカウントがテストユーザーに入っていない（ステップ3-5） |
| `origin_mismatch` / `redirect_uri_mismatch` というエラー | 承認済みの JavaScript 生成元のURLが完全一致していない。`https://` の有無、末尾の `/`、サブドメインのつづりを確認（ステップ3-6） |
| 「Googleで続ける」を押しても何も起きない | スマホのポップアップブロック。iPhone なら 設定 → Safari →「ポップアップブロック」をオフにして試す |
| 許可画面に「空き時間情報の表示」以外の項目が出る | ステップ3-4で余計なスコープが入っている。データアクセスで `calendar.freebusy` 以外を削除して保存 |
| `npm run deploy` でエラーが出る | エラー文をそのまま検索するか、このリポジトリの Issue に貼ってください |

## やってはいけないこと

- **スコープを増やさない**（`calendar` や `gmail` などを足すと、このアプリの安全性の前提が崩れます）
- **クライアント シークレットを保存したり、人に渡したりしない**（このアプリでは使いません）
- **APIキーやサービスアカウントは作らない**（不要です）
- `.env` 以外の場所にクライアント ID を書き込まない（`.env` は git に含めない設定にしてあります）
